## Introduction

Xenoxy is an interpreted programming language, designed with embedding in mind.<br><br>
Xenoxy relies heavily on scopes, which are groups of statements enclosed in ```{}```.

## Variables

Only one built-in type is currently fully supported: a 64-bit signed integer. Boolean values are also generated by comparison
operators, but have very limited support elsewhere in the language.<br>
Variables are only accessible within the scope they are declared in, as well as nested scopes.

### Declaration
Variables in Xenoxy are declared using the ```var``` keyword, that is followed by its name and type.
Each variable is mutable by default.
An uninitialized variable is left as uninitialized, and **should not** be read from until it is written,
due to undefined behaviour.
```
var name: int;
```
A variable can be assigned to in a declaration.
```
var name: int = 10;
```

### Assignment
Variables are assigned to by using ```=```, as many times as needed, however only once per statement.
```
name = 3;
```
Chained assignments of form ```a = b = 3``` are **NOT** supported.

## Operators

Currently Xenoxy supports five arithmetic operators and six comparison operators.<br>
For the arithmetic operators, the arguments have to be integers. The result is also an integer.<br>
For the comparison operators, the arguments have to be integers. The result is a boolean.

### Addition
Addition is done using the ```+``` symbol.
```
a + 1
```

### Subtraction
Subtraction is done using the ```-``` symbol.
```
a - 1
```

### Multiplication
Multiplication is done using the ```*``` symbol.
```
a * 1
```

### Division
Division is done using the ```/``` symbol. The operation performed is integer division, truncating the fractional part.
INT64_MIN / -1 is not handled. Division by 0 is not handled.
```
a / 1
```

### Remainder/Modulo
Modulo is done using the ```%``` symbol. The operation gives back the remainder of dividing the first operand by the second one.
It has the same binding power as Division and Multiplication.
```
a % 2
```

### Equality
Equality is checked using the ```==``` symbol. The operation returns ```true``` when both sides are equal.
```
a == 3
```

### Inequality
Inequality is checked using the ```!=``` symbol. The operation returns ```true``` when both sides are **not** equal.
```
a != 3
```

### Greater than or Equal
Checked using the ```>=``` symbol. The operation returns ```true``` when the left hand side operand is greater than or equal to the
right hand side operand.
```
a >= 3
```

### Less than or Equal
Checked using the ```<=``` symbol. The operation returns ```true``` when the left hand side operand is less than or equal to the
right hand side operand.
```
a <= 3
```

### Greater than
Checked using the ```>``` symbol. The operation returns ```true``` when the left hand side operand is greater than the
right hand side operand.
```
a > 3
```

### Less than
Checked using the ```<``` symbol. The operation returns ```true``` when the left hand side operand is less than the
right hand side operand.
```
a < 3
```

## Control Flow

Xenoxy currently has four control flow keywords:
- ```while``` - Repeats as long as the condition evaluates to ```true```
- ```until``` - Repeats as long as the condition evaluates to ```false```
- ```if``` - Executes scope when the condition evaluates to ```true```
- ```unless``` - Executes scope when the condition evaluates to ```false```

Each control flow keyword is followed by parentheses containing an a boolean expression,
and then a scope.

## Functions

Functions are declared using the ```fn``` keyword, followed by the identifier, arguments and their types in a set of
parenthesis, an arrow symbol (```->```) and the return type.
```
fn name(arg1: int, arg2: int) -> int {}
```
```
fn name2() -> int {}
```

Functions are called with ```()``` with the required arguments placed between the parentheses (comma separated),
so that it matches the function declaration.
```
name(arg1, arg2);
```
```
name2();
```
Return statements allow the caller to receive the result of a function call.
Functions are expected to return a value. Calling a function that reaches its end without executing a return statement
results in undefined behaviour. Functions can return early.
```
return value;
```
